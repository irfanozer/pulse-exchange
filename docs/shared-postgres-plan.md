# Shared PostgreSQL consolidation plan

**Historical database-only alternative, superseded by the combined VM migration.** After West US 2 VM quota approval, the selected route became two separate application VMs and one new shared private PostgreSQL server. Both original databases are copied directly to the new server; PulseExchange does not first move into the old EventHarbor server. Follow [the combined migration runbook](economy-migration.md). This document does not claim that copy, cutover, or retirement is complete.

The full [historical EventHarbor shared PostgreSQL plan](https://github.com/irfanozer/eventharbor/blob/main/docs/shared-postgres-plan.md) remains available for reference. It is not the selected execution procedure and should not be replayed as an intermediate migration.

That alternative includes historical network/capacity observations, separate restricted roles for **both** applications, private connectivity, rehearsal and final-copy checks, a write freeze, Container Apps secret updates, rollback after new writes, and 24-48 hours of capacity observation before source retirement. The selected VM route uses its own runtime attachment and deployment identity instead of switching old Container Apps URLs. Do not delete a source based only on a short smoke test. A stopped source retains storage charges and automatically restarts after seven days.

The approximately $16.09 per 730-hour month server-retirement comparison is before allowances, traffic, backup changes, discounts, and tax. September's shared free database compute/storage amounts were already consumed across historical servers. The screenshot's service costs are month-to-date amounts, not monthly rates. Database consolidation alone does not deliver the approximately $20 total Azure target while existing Container Apps networking remains.

Keep the original Azure deployment files intact. This historical plan does not deploy replacement VMs, change public DNS, remove live networking, or authorize replay of old production/shared-Container-Apps workflows. See [interim-cost-reduction.md](interim-cost-reduction.md) for the recorded API resize and [azure-economy.md](azure-economy.md) for the selected VM layout.
